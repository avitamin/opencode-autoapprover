# Проверка комплекта документации

Дата: **25.09.2026**. Проверялся комплект документации **2.0.0** (после ревизии дизайна ADR-15: градуированная LLM-оценка вместо recognizer), а не установленный OpenCode и не исполняемый плагин.

| Проверка | Результат |
|---|---|
| Текстовые файлы | Корректный UTF-8, LF, завершающий перевод строки |
| Четыре JSON Schema v2 | Валидны как JSON; enum-потолки `autoAllow` и правила связности `assessment` закодированы |
| JSON и JSONC примеры | Синтаксис корректен; guard-примеры структурно соответствуют config schema v2 (`policy.autoAllow` вместо `profile`) |
| Два guard config examples | Соответствуют структурной схеме; placeholders намеренно не являются рабочими настройками |
| Командный corpus | 80 уникальных последовательных IDs; 60 eligible и 20 ask; `expectedAutoWithConformingModel` согласован с `expectedGate`; у каждого fixture есть `expectedModelRiskHint` |
| Ответы модели | Все 34 expectedValid/expectedModelEligibility соответствуют строгому JSON-разбору и schema v2; 6 валидных ответов, 2 eligible; связность (signal↔risk, LOW↔пустые signals, UNKNOWN↔confidence LOW) и дефолтный порог LOW/READ/HIGH перепроверены локально на каждом валидном raw |
| Lifecycle corpus | 54 уникальных последовательных IDs, допустимые effect и call-count поля; добавлена threshold-matrix L51–L54 |
| Review-input и audit schema | Минимальные синтетические объекты приняты валидатором; reason-коды аудита соответствуют пороговой терминологии |
| Relative Markdown links | Все файловые назначения присутствуют; удалённые ссылки и заголовочные anchors этим скриптом не проверялись |
| Compatibility template | NOT_RUN/null сохранены, фактическая квалификация не приписана |
| Упаковка | SHA-256 manifest (42 файла + сам манифест) перегенерирован после ревизии |

## Что результат не означает

Не реализованы и не запущены preflight и threshold-mapper, поэтому соответствие **семантики команд** будущей реализации этим отчётом не доказано. `expectedModelRiskHint` — ожидание честной модели, а не измерение: реальное распределение оценок появится только после live shadow. Lifecycle-сценарии проверены структурно, а не выполнены как конкурентные тесты. Ответы модели проверены локальным независимым скриптом, не TypeScript-кодом будущего плагина.

**Не выполнялись:** установка/запуск плагина, typecheck OpenCode SDK, квалификация host build, реальные permission hooks, команды fixtures, HTTP/API-запросы к reviewer, измерения точности/скорости/стоимости модели. Для этого оставлены отдельные milestones и незаполненные шаблоны отчётов.

Manifest подтверждает целостность этой поставки при сравнении файлов, но не является цифровой подписью издателя. При реализации код и документация будут изменяться; исходный manifest не должен мешать осмысленным изменениям репозитория.
