# Основания новой редакции AGENTS.md

Дата исследования: 29.09.2026. Область: проектные инструкции Codex и OpenCode с DeepSeek/GLM. Это отчёт об организации инструкций, не квалификация плагина и не сравнительный тест моделей.

У DeepSeek в ограниченном поиске найдены модельные и API-руководства; отдельный официальный стандарт AGENTS.md не найден. Это граница поиска, а не утверждение об отсутствии такого документа вообще.

## Решения для этого репозитория

Применение рекомендаций к проекту — инженерный вывод, а не единый шаблон, утверждённый тремя провайдерами.

- Убрать безусловный старт с M0: [backlog](../TASKS.md) и [отчёт](IMPLEMENTATION_STATUS.md) уже содержат результаты этапов. Историю не копировать в постоянные инструкции и не выдавать её за свежую проверку.
- Сохранить иерархию требований и обязательное чтение [SECURITY.md](../SECURITY.md) перед изменением поведения. Код и evidence подтверждают реализацию и проверки, но не отменяют требования.
- Разделить runtime-плагин и агента-разработчика: запрет исполнения оцениваемых команд относится к плагину; разработчик может выполнять разрешённые offline-проверки и отдельно согласованные smoke.
- Сохранить ограничения удаления, runtime-policy, credentials, делегирования и активации auto. Инструкция в репозитории не является технической границей доступа или runtime-разрешением.
- Использовать [FILE_INDEX.md](../FILE_INDEX.md) как полный указатель. В [AGENTS.md](../AGENTS.md) оставить только маршруты по задаче, команды и обязательные правила.
- Сверить команды с [package.json](../package.json). Не добавлять отсутствующий lint; явно назвать `test:live` заглушкой с отказом.
- Целевой объём 100–130 строк выбран для этого проекта; официальные источники не устанавливают такой лимит. Сокращение не должно убирать ограничения безопасности.

## Сохранность прежних ограничений

| Прежняя группа правил | Место в новой редакции |
|---|---|
| V2-only, публичный SDK, strict TS, запрет any/private/V1 | «Инварианты runtime-плагина» и «Код и зависимости» |
| Только текущий ask → allow; native deny, permissions, always, auto-deny | «Инварианты runtime-плагина», с явной неизменностью native allow и других actions |
| Неопределённость, ошибки, лимиты, аудит и потолки порога | «Инварианты runtime-плагина»; все gates определяет SECURITY.md |
| Один вызов LLM; без fallback/retry/subagent/session/transcript и чтения проекта | «Инварианты runtime-плагина» |
| Credentials, provider reuse, отсутствие прямого HTTP adapter | «Инварианты runtime-плагина» и «Правила работы разработчика» |
| Policy и установленный plugin вне рабочего дерева; отсутствие доверия к AGENTS.md | «Инварианты runtime-плагина» |
| Worktree, read-only review, ограничения делегирования, запрет self-approval | «Правила работы разработчика» и маршрут review |
| Безвредный trace, отсутствие ключей и полного окружения | «Правила работы разработчика» |
| Минимальные preflight-проверки, без command recognizer; инертные fixtures | «Инварианты runtime-плагина» и «Правила работы разработчика» |
| Минимальные зависимости, pins/lockfile; без Effect/provider SDK/Go/БД/web/CLI | «Код и зависимости» |
| Недоступный host → NOT_RUN, независимый core/mock, live auto заблокирован | «Код и зависимости» |
| Focused checks, итоговая проверка, diff-review, обновление backlog/status | «Проверки» и «Завершение задачи» |
| Acceptance с тестами, install/off/pins, честные границы live | «Завершение задачи» и маршрут tests/acceptance |
| Русский язык, запрет удаления и обходов, mktemp без очистки | «Общение и границы задачи» и «Правила работы разработчика»; перенесены из инструкций владельца |

Изменён именно стартовый workflow: вместо повторного выполнения первоначального плана агент определяет актуальную задачу. Сохранность защитных условий не зависит от стадии реализации.

## Проверка сценариев применения

| Сценарий | Ожидаемый маршрут и границы |
|---|---|
| Исправить core | Security/requirements → архитектура и затронутые тесты → focused checks → итоговый offline check; без live-вызовов |
| Проверить SDK | V2-контракт → compatibility record → установленные типы; host evidence получать только в разрешённом smoke, недоступное помечать NOT_RUN |
| Только review | Diff → соответствующие контракты/тесты; замечания со сценарием и ссылками, без правок |
| Изменить документацию | Найти владельца в индексе → сверить источники → проверить ссылки/команды/diff; без обязательного runtime suite |
| Подготовить live smoke | INSTALL → operations/manual smoke → host record; отдельно согласованные provider/model/root/consent, без активации в текущей рабочей сессии |

Это статическая проверка маршрутов, не модельный эксперимент. Проверки файлов и оставшиеся границы приведены ниже.

Исходные копии и diff оставлены в `/tmp/autoapprover-agents-LDlvCU`, без автоматической очистки. Файлы проекта на момент проверки untracked, поэтому обычный git diff не показывает эту правку. Исходный SHA256SUMS поставки не обновлялся: это не новая поставка пакета.

При проверке workflow обнаружено отсутствие отдельного repo-documentation-guide; дополнительный guide не создавался, работа выполнена в границах явно утверждённого владельцем плана. Источниками локальных правил служили существующие security/requirements, package scripts и документы-владельцы.

Ограничения: результат не доказывает улучшение качества конкретной модели, фактическую загрузку инструкций новым клиентским сеансом или готовность live auto. Начальные формулировки других документов и исторические отчёты в рамках этой правки не переписывались.
