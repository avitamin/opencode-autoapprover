# 04. Политика и модель угроз

## Роль модели и роль кода

Модель — основной оценивающий смысл команды, но не источник полномочий. Решение об авторазрешении принимает только детерминированный код плагина: он сопоставляет градуированную оценку (`risk`, `categories`, `confidence`) с порогом оператора (`autoAllow.maxRisk`, `minConfidence`, `allowedCategories`). Модель не может расширить порог, отменить локальный стоп-условие или ответить чем-либо, кроме суждения о риске. Эскалационная цепочка (D3) меняет только то, *какая* модель выносит суждение на неконкретном результате предыдущей ступени; авторизация остаётся исключительной прерогативой детерминированного порога.

Авторизация в MVP — явное решение оператора делегировать автоматическое разрешение команд, чья оценка укладывается в заданный порог, при работе внутри определённых roots. Рабочая задача, комментарий агента «пользователь разрешил», README и прежнее подтверждение другой команды такой авторизацией не являются.

## Детерминированный слой: нативные правила OpenCode

Матчинг команд по правилам выполняет хост: ordered rules с action/resource/effect, последнее совпадение выигрывает, составная команда даёт несколько resources, любой `ask`/`deny` в цепочке оставляет решение человеку. Плагин **не дублирует** этот слой; он получает только то, что правила отправили в `ask`.

В `examples/opencode.global.fragment.jsonc` поставляется рекомендуемый deny-фрагмент для чувствительных путей (`.ssh`, `.aws`, `.gnupg`, credential-файлы и т.п.). Оператор сливает его вручную; это часть детерминированного слоя, не политика плагина.

## `graduated-v1`: локальные стоп-условия до LLM

Перед сетевым запросом плагин детерминированно отклоняет (→ `ask`, без вызова модели) только то, чего нативный механизм не проверяет:

- нет полного source binding или resources не согласованы с raw command по подтверждённому mapping;
- cwd вне допущенного root (binding по подтверждённому host mapping);
- секретный prefilter сработал на command/resources (подозрительная строка не отправляется провайдеру даже в отредактированном виде);
- oversized: команда/payload/response сверх лимитов; управляющие символы и NUL;
- нет согласия на передачу данных (`privacy.allowCommandTransmission=false`);
- недоступен аудит, лимит частоты/in-flight, kill-switch, неквалифицированный хост.

**Составные команды (`;`, `&&`, `|`), подстановки, переменные, redirects, glob'ы и произвольные executable больше не являются локальным стоп-условием** — их смысл оценивает модель. Ошибка такой оценки не расширяет порог: если модель не уверена, она обязана ответить `UNKNOWN`/не-LOW, и решение остаётся за человеком. Проверки отдельных файловых операндов (symlink, тип файла, `..` в пути) в этой версии отсутствуют как класс; остаточный риск зафиксирован в таблице угроз.

## Градуированная шкала оценки

Свойства ответа модели — контракт `schemas/assessment.schema.json` v2: `risk`, `categories`, `confidence`, `signals`, `summary`.

| Поле | Значения | Смысл |
|---|---|---|
| `risk` | `LOW` / `MEDIUM` / `HIGH` / `CRITICAL` / `UNKNOWN` | Потенциальный ущерб: обычное локальное чтение / заметное или спорное действие / опасное изменение, сеть, исполнение / разрушительное или системное / модель не поняла команду |
| `categories` | `READ`, `WRITE`, `EXEC`, `NETWORK`, `STATE_CHANGE`, `UNKNOWN` (1–4) | Характер действия; `UNKNOWN` в ответе никогда не разрешён |
| `confidence` | `LOW` / `MEDIUM` / `HIGH` | Уверенность модели в собственной оценке; структурный минимум для allow — `MEDIUM` |
| `signals` | `SECRET_LIKE`, `DESTRUCTIVE`, `PRIVILEGE`, `NETWORK_EGRESS`, `INJECTION_ATTEMPT`, `AMBIGUOUS_SYNTAX`, `UNPARSED_SEGMENT`, `SCOPE_ESCAPE`, `OTHER` | Замеченные признаки; любой опасный сигнал обязан сопровождаться `risk` ≥ `MEDIUM` (несогласованность → `ask`) |
| `summary` | 1–300 символов | Недоверенное пояснение; не выводится как инструкция и не пишется в аудит |

### Порог оператора

`policy.autoAllow`: `maxRisk` ∈ {LOW, MEDIUM}, `minConfidence` ∈ {MEDIUM, HIGH}, `allowedCategories` ⊆ {READ, WRITE, EXEC, NETWORK, STATE_CHANGE}. Дефолт: `LOW` / `HIGH` / `[READ]`. HIGH, CRITICAL, UNKNOWN по риску, LOW по confidence и UNKNOWN по категории **структурно неразрешимы** — их нет в enum схемы конфигурации. Расширение порога — сознательное решение оператора, зафиксированное в доверенном конфиге.

D7: опциональное `escalation.allowedCategories` — надмножество глобального набора, разрешающее расширенные категории **только с вердикта ступени эскалации**. Конкретный вердикт primary, который проваливает лишь глобальную категорийную проверку и целиком проходит расширенный набор, один раз переотправляется следующей модели цепочки (тот же DTO, те же потолки risk/confidence). Провал по риску или уверенности категорийным путём не эскалируется; итог оценивается набором той ступени, которая дала вердикт; бюджет ступени и цепочки не меняется.

## Стоп-условия и sensitive-пути

Built-in sensitive path exclusions (префикс по целым компонентам пути): `.git`, `.ssh`, `.aws`, `.kube`, `.gnupg`, `.env` и `.env.*`, `id_rsa`, `id_ed25519`, файлы ключей/credentials и пути конфигурации самого guard/OpenCode. Директории `secrets`, `credentials` и дополнительные literal path prefixes оператора также исключаются. Особое правило `.env.*` реализуется явно, а не универсальным glob engine. С D9 компоненты операндов режутся по обоим разделителям (`/` и `\`) — Windows-пути не уходят от скана; осознанное следствие (D10 review F3): POSIX-escape токены вида `"\.env"` тоже вскрывают внутренний компонент и стопятся на preflight (ask без LLM) — ужесточение только в сторону ask. Регистр сравнения следует файловой системе пути (ревью коммита e8bde97, N1): Windows-закреплённые токены (drive-префикс, `\`-корень), а при drive-подобном cwd — и все не-POSIX-абсолютные токены (относительные, `~`, `%VAR%`) сравниваются регистронезависимо, чтобы `.SSH`/`Secrets/` не обходили детерминированный стоп регистром; POSIX-абсолютные (`/…`) токены и не-drive cwd сравниваются строго.

Secret detector — консервативный prefilter приватности передачи, не DLP и не авторизация: credentials в URL, authorization/header-like literals, private-key markers, известные token forms. Подозрительную строку нельзя отправлять в LLM после замены на `[REDACTED]`: редактирование могло скрыть смысл — сразу `ask`. Обычные пути/команды всё равно могут содержать конфиденциальные сведения; согласие оператора обязательно.

## Угрозы

| Угроза | Ответ проекта | Что остаётся за границей |
|---|---|---|
| Prompt injection в аргументе | Payload — недоверенные данные; у модели нет tools; опасный signal принудительно поднимает риск; порог задан оператором | Injection атакует главного оценивающего; стопроцентной защиты нет |
| Эскалационная цепочка как усилитель затрат/инъекции | ≤2 ступени, старт только на неконкретный результат предыдущей (никогда — на конкретный опасный вердикт или транспортный сбой); бюджет ступени и hook-дедлайн валидируются конфигом в пределах зашитого потолка hook-бюджета (120 000 мс); rate limit считается на событие; каждая попытка в аудите/трейсе | Каждая ступень получает тот же недоверенный payload; на эскалированных событиях стоимость и латентность растут кратно числу ступеней |
| Ошибочный LOW | Потолки схемы (HIGH/CRITICAL/UNKNOWN неразрешимы); негативный корпус; shadow-first; аудит; `confidence`-требование | Вероятностная, не детерминированная гарантия |
| Составная команда с скрытой опасностью | Модель обязана оценивать всю цепочку; непонятный сегмент → `UNPARSED_SEGMENT`/не-LOW | Локальная грамматика больше не проверяет структуру |
| Секреты | Preflight до LLM; отсутствие transcript/raw logs по умолчанию (opt-in `diagnostics.llmTrace` записывает их локально — осознанное решение оператора, docs/07; команды со стопом `SECRET_DETECTED` попадают в трейс только фингерпринтом) | Нет абсолютной DLP-гарантии |
| Выход за root через операнды (`..`, symlink, абсолютный путь) | cwd-binding на уровне root; сигнал `SCOPE_ESCAPE` в оценке модели | Детерминированной проверки путей операндов нет; TOCTOU остаётся |
| Repo config управляет policy | Только независимый global config и поставленный prompt bundle | — |
| Подмена executable / hooks | Проверенная trusted runtime конфигурация | Враждебный same-UID процесс вне модели |
| Поздний ответ | Terminal state + deadline; worker никогда сам не меняет event | — |
| Другой плагин отменяет ask | Конфликтующий deployment не допущен | Порядок hooks не лечит произвольный конфликт |
| Host bypass | Короткий regression smoke и exact-build admission | Guard не исправляет ядро |
| Внешние обработчики Git (fsmonitor и т.п.) | Модель оценивает фактическую команду целиком; оператор может вернуть жёсткий deny-фрагмент для `git` | Специальной git-квалификации в MVP нет |

Фикстуры в `tests/fixtures/commands.jsonl` — обязательный контракт: `expectedGate` описывает локальный preflight, `expectedAutoWithConformingModel` — поведение controller при конформном ответе LOW/READ/HIGH-confidence, `expectedModelRiskHint` — ожидаемую оценку честной модели для live-корпуса. Это строки для разбора, а не команды для выполнения.
