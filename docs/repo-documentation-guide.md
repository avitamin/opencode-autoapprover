# Правила ведения документации репозитория

Этот guide задаёт маршрут для документационных изменений в `opencode-autoapprover`. Он не заменяет [AGENTS.md](../AGENTS.md) и документы с требованиями.

## Источники и приоритет

1. Новые явные указания владельца и ограничения [AGENTS.md](../AGENTS.md).
2. Для безопасности и целевого поведения: [SECURITY.md](../SECURITY.md), затем [docs/01-requirements.md](01-requirements.md), JSON-схемы в `schemas/` и их семантические правила.
3. Для фактического состояния: текущий `src/`, `package.json`, установленные типы SDK, тесты и датированные `compatibility/evidence-*.md`. Отчёты `reports/` сводят доказательства, но не заменяют их.
4. Остальные тематические документы и примеры. Примеры не являются активной конфигурацией.

При расхождении целевого контракта и кода описывать оба состояния явно; не объявлять безопасность или готовность по одному лишь примеру либо историческому PASS.

## Приватность документации

Не переносить в документацию значения из личного конфига, журналов или окружения оператора: имена пользователей, абсолютные пути его домашнего каталога и workspace, ключи, endpoint/account, текст рабочих команд и содержимое файлов. Для инструкций использовать `~`, стандартные XDG-переменные или явно обозначенные заполнители; для evidence — обезличенные обозначения вроде `<workspace-root>` с сохранением проверяемого результата. Точное значение из текущей установки сообщать в чате только если оно необходимо для ответа, без записи в репозиторий. Перед завершением документационной правки искать персональные пути и секретоподобные строки в изменённых файлах.

## Проверка по типу изменения

| Изменение | Сверить с | Проверить |
|---|---|---|
| Конфигурация и режимы | `src/config.ts`, `schemas/config.schema.json`, `examples/guard.*.json`, `docs/05-configuration.md` | Поля, значения, перезагрузку, границы consent |
| Аудит и диагностика | `src/audit.ts`, `src/controller.ts`, `schemas/audit.schema.json`, `docs/07-lifecycle-and-audit.md` | Реальные outcome/reason, состав записи, ротацию и ограничения вывода |
| Установка и host smoke | `package.json`, `scripts/`, `tests/manual/`, `compatibility/host-contract.json` и датированное evidence | Команды, точные версии, PASS/FAIL/NOT_RUN и путь установленной копии |
| Поведение runtime | Затронутый `src/`, схемы и тесты | Сохранность gates, позитивный и ошибочный путь, критерии приёмки |

Для правок только документации проверить существование локальных ссылок, команды по `package.json`, Markdown и diff; runtime suite не нужен. Для правок поведения выполнить проверки по [AGENTS.md](../AGENTS.md) и обновить статус реализации и acceptance-связи.

## Навигация и отчётность

Новый постоянный файл вне `FILE_INDEX.md` добавить в [FILE_INDEX.md](../FILE_INDEX.md). При изменении существующего владельца темы достаточно проверить актуальность его индексной строки. `README.md` обновлять, когда меняется маршрут первого знакомства или текущий уровень готовности.

В итоговом сообщении разделять выполненные offline-, host- и live-проверки; не переносить исторический результат в текущий прогон. Писать по-русски, оставляя код, команды и точные пути в исходном виде.
