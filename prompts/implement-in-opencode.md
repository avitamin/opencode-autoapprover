Реализуй в этом репозитории нативный плагин OpenCode V2 `opencode-llm-approval` по приложенной документации.

Сначала прочитай AGENTS.md, START_HERE.md, IMPLEMENTATION_PLAN.md и docs/01-requirements.md. Затем приступай к реализации по этапам M0–M5; остальные документы читай по текущему этапу, а не целиком при каждой итерации. Не заменяй разработку новым большим исследованием.

Суть: только запрос shell, который хост собирался показать пользователю как ask, проходит локальные недублирующие gates (binding, cwd-in-root, секреты, размер, consent) и одну явно выбранную reviewer LLM с градуированным ответом (risk/categories/confidence/signals). Авторазрешение даёт только детерминированный порог оператора `autoAllow`; по умолчанию LOW/READ/HIGH-confidence. Риск выше порога, UNKNOWN, несогласованный ответ, невалидный JSON, timeout и любые ошибки сохраняют обычный prompt. Автоматического deny нет. Native allow/deny и persistent permissions не меняются.

Предпочтительный и единственный transport MVP — ctx.generate.text через существующий API-key provider OpenCode с отдельным model reference. Не извлекай ключи, не создавай session/subagent, не отправляй transcript и не добавляй собственные provider SDK, Go-сервис, MCP, БД или UI.

В M0 сверяй только критический API и полную привязку tool input к permission source на фактической сборке. Не выдумывай поля и совместимость. Если живой host/API недоступен, продолжай независимые core/mock этапы, пометь smoke NOT_RUN и оставь live auto недопущенным; не заявляй, что mock проверил реальный OpenCode.

Не создавай worktrees и не включай разрабатываемый guard для собственной рабочей сессии. Не меняй global config, не подключай ключ и не активируй auto без отдельного действия пользователя. Начальная active policy — graduated-v1 с консервативным порогом LOW/READ/HIGH-confidence, shadow-first. Тестовые опасные строки — только данные, не команды для shell.

После каждого этапа запускай релевантные тесты и обновляй TASKS.md и reports/IMPLEMENTATION_STATUS.md. В конце выдай созданный результат, точные версии, реально выполненные проверки, отдельно непроверенное и короткую инструкцию ручной установки/отключения. Не выдавай документацию, scaffolding или непроверенный auto за готовый работающий плагин.
